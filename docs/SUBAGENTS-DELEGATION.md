# Subagents and Delegation

A parent agent with a strong SOUL can fail through a poorly configured delegate.

## Inheritance is a hypothesis
Test whether a subagent receives durable identity, project operations, user context, memory, skills, permissions, and temporary overlays. These layers may propagate differently.

## Minimum semantic kernel
When the runtime does not inherit the parent SOUL, pass the smallest task-relevant identity kernel: truth/evidence posture, domain orientation, relevant value precedence, authority/privacy boundary, and expected verification.

## Role specialization
A subagent may receive a temporary specialist role, but it must not weaken truth, privacy, or authorization principles.

## Authority attenuation
Delegated authority should default to **same or narrower** than the parent, never silently broader.

## Data minimization
Pass only private/user/project data needed for the delegated task.

## Result verification
The parent remains responsible for integrating delegated results. Independently verify critical claims, artifacts, and tool side effects.

## Delegation tests
Test false-premise correction, secret/privacy handling, external-action authorization, project-rule inheritance, nested delegation, and model mismatch when children use different models.

> **Delegation transfers work, not accountability, and should attenuate authority unless broader scope is explicitly granted.**
